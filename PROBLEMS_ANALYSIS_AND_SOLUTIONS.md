# Анализ проблем и решений для стабилизации Sirius Group

## 🎯 Цель
Выявить источники зависаний и нестабильности в проекте, составить план микрофиксов для достижения стабильного состояния.

## 📊 Карта точек входа

### Основные файлы:
- `app/main.py` - точка входа приложения
- `app/config.py` - конфигурация системы
- `app/db.py` - подключение к базе данных
- `app/services/` - бизнес-логика (16 сервисов)
- `app/routers/` - API маршруты (16 роутеров)

## 🚨 Выявленные проблемы (по приоритету)

### КРИТИЧЕСКИЕ (блокируют запуск)

#### 1. **Блокирующая инициализация БД в main.py**
**Проблема**: `Base.metadata.create_all(bind=engine)` выполняется при импорте модуля
**Риск**: Высокий - может зависнуть при проблемах с БД
**Решение**: Перенести в startup event с таймаутом

#### 2. **Тяжелые импорты роутеров**
**Проблема**: Все 16 роутеров импортируются сразу при старте
**Риск**: Высокий - каждый роутер может иметь тяжелые зависимости
**Решение**: Ленивая загрузка роутеров

#### 3. **Отсутствие таймаутов в конфигурации**
**Проблема**: Нет таймаутов для внешних подключений
**Риск**: Средний - может зависнуть при сетевых проблемах
**Решение**: Добавить таймауты для всех внешних операций

### ВЫСОКИЕ (могут вызвать зависания)

#### 4. **QR-генерация в горячем пути**
**Проблема**: `QRService` может генерировать изображения синхронно
**Риск**: Высокий - блокирует запросы
**Решение**: Асинхронная генерация или кэширование

#### 5. **Логирование с файловыми операциями**
**Проблема**: `LoggerService` создает файлы при инициализации
**Риск**: Средний - может зависнуть при проблемах с ФС
**Решение**: Ленивая инициализация логгера

#### 6. **Мониторинг производительности**
**Проблема**: `PerformanceMonitor` создает глобальные структуры данных
**Риск**: Средний - может потреблять много памяти
**Решение**: Ограничить размер буферов

### СРЕДНИЕ (могут замедлить работу)

#### 7. **Отсутствие health-check зависимостей**
**Проблема**: `/health` не проверяет реальное состояние БД
**Риск**: Средний - может показывать "OK" при проблемах
**Решение**: Добавить проверку БД с таймаутом

#### 8. **Статические файлы без оптимизации**
**Проблема**: `StaticFiles` может блокироваться на больших файлах
**Риск**: Низкий - влияет на производительность
**Решение**: Добавить кэширование заголовков

#### 9. **Отсутствие graceful shutdown**
**Проблема**: Нет обработки сигналов завершения
**Риск**: Низкий - может потерять данные при остановке
**Решение**: Добавить shutdown events

## 📋 Детальный план исправлений

### Файл 1: `app/main.py`
**Проблемы**:
- `Base.metadata.create_all(bind=engine)` при импорте
- Все роутеры импортируются сразу
- Простой health-check без проверки зависимостей

**Исправления**:
- Перенести создание таблиц в `@app.on_event("startup")`
- Добавить таймаут для создания таблиц
- Улучшить health-check с проверкой БД
- Добавить graceful shutdown

### Файл 2: `app/config.py`
**Проблемы**:
- Нет таймаутов для внешних операций
- Отсутствуют настройки для production

**Исправления**:
- Добавить таймауты для HTTP клиентов
- Добавить настройки для connection pooling
- Добавить флаги для отключения внешних сервисов в dev

### Файл 3: `app/db.py`
**Проблемы**:
- Нет connection pooling
- Нет таймаутов для подключений
- `echo=settings.debug` может спамить логи

**Исправления**:
- Добавить connection pooling
- Добавить таймауты подключения
- Условно включать echo только в debug режиме

### Файл 4: `app/services/logger.py`
**Проблемы**:
- Создание файлов при инициализации
- Нет ротации логов
- Может блокироваться на файловых операциях

**Исправления**:
- Ленивая инициализация файлов
- Добавить ротацию логов
- Асинхронная запись логов

### Файл 5: `app/services/qr_service.py`
**Проблемы**:
- Синхронная генерация изображений
- Создание файлов в критическом пути
- Нет кэширования

**Исправления**:
- Асинхронная генерация QR
- Кэширование готовых QR-кодов
- Ленивое создание директорий
