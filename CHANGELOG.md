### ✅ Исправления

#### app/main.py
- **Проблема**: `Base.metadata.create_all(bind=engine)` выполнялся при импорте модуля, что могло вызвать зависание
- **Решение**: Перенес создание таблиц в `@app.on_event("startup")` с таймаутом 10 секунд
- **Добавлено**: 
  - Асинхронная инициализация БД с таймаутом
  - Graceful shutdown event
  - Улучшенный health-check с проверкой БД
  - Логирование процесса инициализации
- **Результат**: ✅ Синтаксис OK, ✅ Импорты OK

### 🔧 Технические детали

#### Startup Event
```python
@app.on_event("startup")
async def startup_event():
    # Создание таблиц с таймаутом 10 сек
    await asyncio.wait_for(
        asyncio.get_event_loop().run_in_executor(
            None, lambda: Base.metadata.create_all(bind=engine)
        ),
        timeout=10.0
    )
```

#### Health Check
```python
@app.get("/health")
async def health_check():
    # Проверка БД с таймаутом 2 сек
    await asyncio.wait_for(
        asyncio.get_event_loop().run_in_executor(
            None, lambda: engine.execute(text("SELECT 1"))
        ),
        timeout=2.0
    )
```

#### app/services/qr_service.py
- **Проблема**: Синхронная генерация QR-кодов блокировала запросы
- **Решение**: Добавил асинхронную генерацию с кэшированием и таймаутами
- **Добавлено**:
  - Асинхронный метод `generate_qr_image_async()` с таймаутом
  - Кэширование готовых QR-кодов в памяти
  - Обработка ошибок и логирование
  - Обратная совместимость со старыми методами
- **Результат**: ✅ Синтаксис OK, ✅ Линтер OK

#### app/services/logger.py
- **Проблема**: Создание файлов при инициализации могло блокировать запуск
- **Решение**: Добавил ленивую инициализацию с ротацией логов и обработкой ошибок
- **Добавлено**:
  - Ленивая инициализация файлового логирования
  - Ротация логов (10MB, 5 файлов)
  - Fallback на консольное логирование при ошибках
  - Метод close() для graceful shutdown
- **Результат**: ✅ Синтаксис OK, ✅ Линтер OK

#### app/services/monitoring.py
- **Проблема**: Неограниченные буферы могли потреблять много памяти
- **Решение**: Добавил ограничения размеров буферов и очистку старых данных
- **Добавлено**:
  - Настраиваемые лимиты для буферов (100 запросов, 50 БД запросов, 20 типов ошибок)
  - Ограничение количества типов ошибок
  - Метод cleanup_old_data() для очистки старых данных
  - Улучшенная обработка ошибок
- **Результат**: ✅ Синтаксис OK, ✅ Линтер OK
